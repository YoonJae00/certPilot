# 데모핀테크 백업 및 복구 정책

- 문서번호: OPS-BAK-001
- 제정일: 2023-02-13
- 최종 개정일: 2023-02-13
- 승인: CISO

## 1. 목적

본 정책은 데모핀테크의 중요 정보와 데이터베이스를 정기적으로 백업하고, 장애 또는
재해 발생 시 복구할 수 있도록 하기 위한 기준을 정한다.

## 2. 적용 범위

정보자산 목록상 중요도 "상"으로 분류된 자산 전부에 적용한다. 구체적으로는 회원
데이터베이스(AST-001), 송금 원장 데이터베이스(AST-002), 비밀정보 저장소(AST-014)를
포함한다.

## 3. 백업 대상과 주기

| 대상 | 백업 방식 | 주기 | 보관 기간 | 저장 위치 |
| --- | --- | --- | --- | --- |
| 회원 DB | RDS 자동 스냅샷 | 일 1회 (03:00 KST) | 30일 | AWS 관리형 스냅샷 |
| 송금 원장 DB | RDS 자동 스냅샷 | 일 1회 (03:20 KST) | 30일 | AWS 관리형 스냅샷 |
| 송금 원장 DB | 논리 덤프 | 주 1회 (일요일) | 90일 | S3 backup 버킷 (AST-005) |
| 애플리케이션 설정 | Git 저장소 | 변경 시 | 무기한 | 외부 SaaS |
| 로그 데이터 | 수명주기 규칙 이관 | 일 1회 | 1년 | S3 backup 버킷 |

## 4. 백업 데이터 보호

- S3 backup 버킷은 서버 측 암호화(SSE-S3)를 적용한다.
- 버킷 정책으로 퍼블릭 접근을 차단한다.
- 백업 데이터 접근 권한은 운영팀 2명에게만 부여한다.
- 백업 원격지 이중화는 비용 문제로 도입하지 않았다. (단일 리전 보관)

## 5. 백업 수행 확인

백업 성공 여부는 매일 09:00 운영팀 채널로 자동 알림된다. 실패 시 담당자가 재실행하고
결과를 운영 일지에 기록한다.

2024년 백업 실패 이력:

| 일자 | 대상 | 원인 | 조치 |
| --- | --- | --- | --- |
| 2024-02-19 | 송금 원장 논리 덤프 | 디스크 공간 부족 | 용량 증설 후 재실행 |
| 2024-07-08 | 회원 DB 스냅샷 | 일시적 API 오류 | 자동 재시도로 성공 |

## 6. 복구 절차

1. 장애 접수와 영향 범위 판단 (운영팀장)
2. 복구 대상 스냅샷 또는 덤프 선정
3. 복구용 인스턴스 생성 및 데이터 적재
4. 데이터 정합성 확인 후 서비스 전환
5. 복구 완료 보고와 원인 분석

## 7. 복구 테스트

본 정책 제7조는 "반기 1회 이상 복구 테스트를 수행하고 결과를 기록한다"고 정하고 있다.

**그러나 본 문서 작성 시점까지 복구 테스트를 수행한 기록이 없다.** 정책 제정
이후 2023년 상·하반기, 2024년 상·하반기 모두 테스트가 수행되지 않았으며, 복구
소요 시간(RTO)과 목표 복구 시점(RPO)도 정의되어 있지 않다. 2023년도 위험평가에서
R-04 항목으로 식별되었으나 이행계획이 완료되지 않은 상태이다.
