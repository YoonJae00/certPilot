# CertPilot 구현 계획 (Task 0 산출물)

> 작성 2026-08-25. PRD v0.1(@docs/PRD.md) 전체와 CLAUDE.md를 읽고 정리한 이해 범위·질문·리스크.
> 자율 진행 모드로 빌드하므로, 각 질문에는 **채택한 기본값**을 함께 기록한다. 팀이 다른 답을 주면 해당 지점만 고친다.

## 1. 이해한 범위

- 목표: ISMS-P 101개 항목 기준 모의심사 → 근거 표시 → 운영명세서 초안 → AWS 증적 수집·drift 감지 → 심사원 승인 게이트 → 내보내기를 **한 번에 끝까지** 보여주는 시제품 (D1~D5).
- 스택: FastAPI 단일 백엔드 + Next.js 14, Postgres16+pgvector, Celery+Redis, MinIO(S3 대용), boto3 읽기 전용.
- AI 원칙: 근거 없으면 unknown 강제(서버 후처리), 규칙이 LLM을 이김, LLM은 초안만, 마스킹 후 전송, temperature 0.
- 작업 순서: 부록 B Task 1~12, 태스크마다 `make check` 녹색이 완료 조건.

## 3. 리스크 (PRD §13에 더해 실행 관점)

1. **안내서 PDF 파싱**: 표·병합 셀 많음. `kb_build.py`는 실패 항목 리포트를 남기고, 파싱 결과를 커밋된 `criteria.json`으로 고정(소스 오브 트루스)한다. 101/16/64/21 테스트가 게이트.
2. **e2e(Playwright)**: 로컬 도커 스택 필요. CI에서는 단위 테스트만, e2e는 로컬 `make e2e`로 분리.
3. **10분 내 모의심사**: FakeProvider에서는 문제없음. 실 LLM에서는 동시 5 병렬로 달성 예상, 비용 로그로 검증.
4. **범위 대비 시간**: PRD §13 대응대로 F4는 운영명세서 우선, 정책 초안은 템플릿 채움 수준. Task 7b(GitHub)는 인터페이스만.

## 4. 실행 순서

PRD 부록 B 그대로 Task 1 → 12. 각 태스크는 Worker(opus)에게 브리프로 위임하고, Advisor가 diff·`make check`로 검증 후 커밋한다. 독립적인 부분(예: Task 2 지식베이스와 Task 3 데이터 모델)은 병렬 위임한다.
